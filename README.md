# Programme Manager

A single-file, locally hosted budgeting and programme management app — a "Notion-light database tool with a budgeting addition". No installation, no server, no dependencies: open `index.html` in a desktop browser (Chrome or Edge recommended).

1. Getting started
   a. Open `index.html` in your browser (double-click the file).
   b. Enter a programme name on the start screen — each programme is a separate instance.
      i. Data autosaves to the browser as you type (see the "Saved" stamp in the header).
      ii. Every programme created on this computer is listed on the start screen.
      iii. A "Welcome & guide" page is created as the first Notes page of every programme — a friendly, in-app version of this README. Delete it whenever you like (it behaves like any other Notes page).
      iv. Switch or combine programmes from the dropdown beside the programme name: pick another programme to jump to it, pick "All programmes (overview)" for a read-only, unified roll-up, or pick "＋ New programme…" to create a fresh one. Each programme in the list is tagged with where it saves — its file name, or "browser only" if it has no file yet.
         1. The overview gives one budget across every programme (per-programme subtotals plus a grand total), one calendar showing every programme's events and due/completed actions, and one action list grouped under each programme's name.
         2. Switch back to any single programme to edit it.
      v. The start screen shows the same "where it saves" tag beside each programme, so you can see at a glance which programmes are on a real file versus only in the browser.
   c. How saving works — two copies are always kept: this browser (automatic) and a file on your computer (the one you own and can back up).
      i. This browser: everything autosaves automatically as you type. It stays on this computer, in this browser only — clearing site data or using another browser/computer won't have it. Convenient, but not something to rely on as your only copy.
      ii. A file on your computer: a portable `.programme.json`. Back it up, move it, email it, or drop it (or the 📝 Markdown snapshot) into an AI model.
      iii. One honest status pill in the header always tells you where the FILE stands, so browser-autosave can't hide a stale file:
         1. "⚠ Browser only" (amber) — not saved to a file yet.
         2. "✓ Saved · name.json" (calm) — the file is up to date. This only ever shows after a real write to your file succeeds — it never shows for a download. A small "auto" tag next to it means auto-sync is on, so the file updates by itself after every change; without the tag, the file is current because you last saved it and will need a save after your next edit.
         3. "● Unsaved → name.json" (amber) — you have changes the file doesn't have yet.
         4. "⚠ Reconnect · name.json" (amber) — the file needs a fresh permission click; click and Save once (it writes back to the same file, never a new one).
         5. "⚠ Relink · name.json" (amber) — the browser dropped the file link entirely on reload; use Open to pick the same file again.
         6. "⬇ Downloaded copy" (amber) — a copy went to your Downloads and is NOT linked; use Save to file to link a folder file instead.
      iv. Click the pill for one tidy menu. Before a programme has a file, the only save option is "Save to a file…" — a Save As that makes you pick the location, so nothing is written blindly. Once it's linked, the menu becomes "Save now" plus a separate "Save As…" (choose a new name or folder — this is how you move a programme's file; your computer keeps the old one to delete). The menu also has Open a file, Download a copy, and a "Keep file in sync automatically" toggle. Ctrl/Cmd-S saves.
      v. Opening a file loads it back into its own programme — it never creates a second copy in the dropdown. The app matches the file to the programme it belongs to (by the file itself, or failing that its name) and:
         1. If the file and the browser copy already match, it just reconnects silently — no pop-up.
         2. If they differ, one clear confirm appears, naming the programme and saying whether the file or the browser copy is newer. It offers "Keep browser version (save it to a file)" so you don't lose unsaved edits, "Load the file (replace browser copy)", or Cancel. Cancel truly cancels — nothing is loaded, nothing is duplicated.
         3. Only a file whose programme you don't have yet opens as a new programme.
         4. If you already ended up with a stray duplicate from the old behaviour, switch to it, open ⚙ Settings, and "Delete this programme from this browser" — your saved `.json` file is unaffected.
      vi. The app can only show the file's name (e.g. `henderson-hubs.programme.json`), never its full folder path, and it can't open the containing folder for you. Browsers deliberately hide both for privacy — a web page is never told where on your disk a file lives. To find a saved file, use your operating system's search for its name, or note the folder yourself when you first pick it in the Save dialog.
      vii. Important — opening from a double-clicked file (a `file://` page) vs a local address. Browsers only remember permission to write to a file for pages served over a web address (`http://localhost` or `https://`), never for a double-clicked `file://` page. So if you open `index.html` by double-clicking it:
         1. You can still save to a specific file you choose, and saves within that session write straight to it.
         2. But each time you reopen the app the browser forgets the permission, so the pill shows "Reconnect" (or "Relink") and you click Open/Save once to point it back at the same file. It never silently spawns a new file or a Downloads copy behind a green tick.
         3. To make the file link stick automatically with no per-session click, run the app from a local address instead of double-clicking. From a terminal in the folder holding `index.html`, run a tiny static server and open the address it prints — for example `python3 -m http.server 8000` then visit `http://localhost:8000/`, or `npx serve` . Save to your file once there and it stays linked and in sync across restarts.
      viii. When you save a programme to a file, it stays in sync automatically by default, so the file never silently falls behind. Turn the toggle off to save the file only when you click Save (the pill then shows "● Unsaved" whenever the file is behind). Each programme keeps its own file, so saving one never overwrites another, and switching programmes switches the file with it.
      ix. If the browser's storage ever fills up, the app warns you loudly ("⚠ NOT saved") instead of losing changes silently, and prompts you to save to a file and free space (trim large notes, empty 🗑 Trash).
      x. Chrome or Edge can save directly to a file you choose. Other browsers fall back to a download (the pill shows "💾 Download").
   d. 📥 Data is the export/import hub.
      i. Bulk download a full copy: 📊 Excel workbook (every page), 📝 Markdown snapshot, 💾 JSON (all data) or the financial CSV. A second row of buttons exports a single page to Excel on its own — Overview, Forecast, Actions, Calendar, Notes or Links.
      ii. Bulk upload: a full programme file (JSON) updates all information in the app — budget, forecast, calendar, actions and notes — in place; a financial CSV updates just contracts/POs/lines/invoices.
      iii. Financial CSV: one row per item, ordered contract → po → line → invoice, matched on contract/PO/line/invoice numbers — re-uploading updates existing items instead of duplicating them. `import-template.csv` is a worked example.
      iv. A `po` row with a blank `contract_number` becomes a standalone PO; put its supplier in the `supplier` column. Contracts also carry a `what` (contract name) column. If a file has no recognised `type` column, the importer says so clearly instead of silently doing nothing.
   e. Data entry: Tab moves to the next field, Enter moves down the column (Excel-style), and long text fields wrap as you type.
      i. PO lines can be copied (⧉) and pasted (📋) whole — the target keeps its own line number.
      ii. Tab-separated values pasted from Excel fill across a PO line row, or across consecutive forecast periods.
      iii. Contracts, POs, PO lines, forecast lines, tasks and links can be reordered by dragging their ⠿ handle (within their own group).
      iv. Contracts and POs fold/unfold (▼/▶) so long lists stay manageable.
   f. Shortcuts: Ctrl/Cmd-K opens Find — jump to any task, contract, PO, PO line, event, forecast line or notes page. Ctrl/Cmd-Z undoes your last change and Ctrl/Cmd-Y (or Ctrl/Cmd-Shift-Z) redoes it (this is a programme-wide undo, separate from the browser's own text undo while you're typing in a field). Ctrl/Cmd-S saves to the file.
   g. Customise in ⚙ Settings: task states, task priorities, task tags, calendar tags and forecast statuses.
   h. 🗑 Trash — deletes are recoverable. Deleting a contract, PO, PO line, invoice, forecast line, task, event, notes page or link moves it to the Trash (last 50), where it can be restored or permanently purged. Undo (Ctrl/Cmd-Z) also reverses deletes and other edits.
2. Tabs
   a. Budget
      i. Overview — a read-only summary with one row per contract and per standalone PO (no double-counting): for what, supplier, contract #, PO #s, line count, original budget, variations, current value, end date, actuals, remaining. The "For what" column shows the contract's name (falling back to the contract number so a row is always identifiable). Nothing is edited here; → jumps to the detail, and the templated/custom views and archived filter still apply.
         1. Time and multi-select filters (the same controls as Forecast & phasing): the Supplier, Contract # and WBS filters are Excel-style tick-box dropdowns (search, tick any number of values), and ticking "in FY" scopes the Actuals column to a financial-year window (the financial-year picker is shared with Forecast & phasing). Remaining always shows the true budget left, regardless of the window.
      ii. Contracts · POs · Lines — contracts (supplier, supplier number, total value, end date, contract name) hold POs, which hold PO lines (line number, WBS element, spend code, GL code, value). Variations are recorded against the contract: original value + variations = current contract value, and the reconcile badge checks PO lines against that current value. POs can also be added standalone with no contract; "+ PO" opens a form with the contract shown as n/a for standalone, a default line 10, and "+ Add line" for more (each with value, WBS, spend and GL code). Invoices attach to each PO line. Excel-style multi-select tick-box filters (Supplier, Contract #, WBS) and view templates (Active, Everything, Unreconciled, Archived only) narrow the list; archived contracts/POs/lines are hidden unless you pick a view that shows them.
      iii. Forecast & phasing — quarterly only, following the July–June financial year (Q1 FY27 = Jul–Sep 2026); a "Financial year" picker sets the window and Excel-style multi-select tick-box filters (Supplier, Contract #, WBS) narrow it. Rows are contracts, standalone POs, and a "Planned (not yet contracted)" bucket; ▶ expands one to manage its forecast lines. You phase on the forecast lines only — the row above is the read-only sum of its lines. Lines under a contract/PO default to status "Committed" (options: Committed / In progress / Complete) and pick a PO + PO line; lines in the Planned bucket default to "Planned" and take a manual estimated value and likely supplier. Each line also carries a "what for", Start/End dates. A new line auto-splits evenly across the visible year (25% a quarter over four quarters); adjust any cell by typing a dollar value (`5,000`) or a percentage (max 100). The percentage is of that line's remaining budget — its PO-line value minus actuals invoiced to date (for a Planned line, its estimated value). Forecast lines can be archived (🗄) and hidden with the "show archived" toggle. "act" shows invoiced actuals per period; paste tab-separated values from Excel to fill several quarters at once.
         1. Actual vs forecast — each quarter counts the greater of its forecast or its actual toward the budget, so invoicing a quarter you already forecast no longer double-counts and tips the line "over budget". Where an actual differs from the forecast a Δ chip flags it in the cell (red when the actual exceeds the forecast, green when it is under).
         2. Columns — Total contract value, Actuals (period) (only what is invoiced inside the chosen financial-year window), Total remaining (total contract value − actuals to date), the quarters, Forecast Σ, then Over / Under forecast (the budget still uncommitted once each quarter counts the greater of forecast or actual — negative means forecast + spend exceed the budget). Set the window to a year and read those columns to see, at a glance, whether there is enough budget for the period.
         3. Convert a planned spend to a contract — set a Planned item's status to "Committed" (or use its "→ Contract" button) to open a form that creates the contract, PO and PO line (or attaches to an existing contract/PO, or a standalone PO). The forecast line keeps its phasing through the conversion, and any task, event or note linked to the planned spend follows through and re-points to the new contract (a ↩ badge on the line shows how many links are attached).
      iv. Views — templated views (Full detail, Financial summary, By supplier, By location, Contract register) plus a custom view builder (choose columns, grouping, filter) with saved views.
      v. Archiving — contracts, POs, PO lines and budget lines all have an archive button (🗄) alongside delete; archived items are hidden from default views and dropdowns but keep their history and can be shown or restored (↩) at any time.
   b. Calendar
      i. Month view by default; switch to week or day. In the month grid every week row is the same height, so the layout stays steady as you move between months; a day with more items than fit shows the first few plus a "+N more" link that opens that day.
      ii. Tags (Milestone, Meeting, Hui, Activation/Activity, Deadline — customisable in ⚙ Settings) colour and filter events; each event also has an Organiser field (with an Excel-style multi-select Organiser filter in the toolbar), and event notes are the place for hui notes.
      iii. Tasks with due dates appear automatically on the calendar as an empty box (☐, i.e. not yet done), and completed actions show on their completion date as a bare tick (✓). The ☐ Tasks and ✓ Done chips in the toolbar filter task and completed-action pills in or out.
   c. Actions
      i. Endlessly nestable task list — Enter adds the next task, Tab/Shift-Tab nests/un-nests; all top-level items sit tight against the left edge and children indent under a guide.
      ii. Each task has name, a priority flag (click to cycle), owner/person, tags, links, an optional start date, due date, an automatic last-actioned date, completion date, state (a dropdown — pick any state directly, including reversing a completed task back to "To do" without having to reopen it) and notes. The last-actioned date updates itself whenever you touch the task and is shown read-only in small text beside the name (it is no longer hand-editable). The start date is shown progressively — with none set, only a small muted start icon sits beside the due date; click it to expand the field. A start date pairs with the due date to describe a span of work, which the Roadmap view draws as a bar. Notes stay hidden under the task — a 🗒 indicator appears when a note exists, and clicking it expands/collapses the note. Nesting and adding sub-tasks are keyboard-driven — Enter adds the next task, Tab / Shift-Tab nests / un-nests — so those row buttons were removed to keep the row clean (tags, link, notes and delete remain; headers keep their ＋ task / ＋ header buttons). Due dates carry a graded colour cue so time-to-go reads at a glance — bright red overdue, red-orange today, orange in the next few days, green within the week, teal a week or two out, blue further away (a small key sits under the list) — and the date's soft bar also fills up as the due date approaches (a thin sliver a month out, brimming full today/overdue), giving a second at-a-glance read. The start date has its own cooler cue — green once work has started or starts today, blue when it starts soon, a faint blue further out. Hovering a date shows exactly how many days away it is. The owner, action buttons, start and due columns stay in fixed, aligned columns no matter how deeply a task is nested or how many tags it carries — only the name, its tags and the last-actioned stamp flex; everything to the right lines up.
      iii. "+ Header" inserts a section header to group tasks (e.g. by programme or workstream), and headers can contain sub-headers ("+ header" on a header); each header shows as a light-orange band, the same colour used for lanes on the timeline. "★ This week" shows a focused, priority-sorted list of everything with a priority flag or a due date this week.
      iv. Empty tasks aren't kept — if you add a task and leave it blank, it's dropped when you switch tabs.
      v. "show completed" (top-right) toggles finished tasks in or out of the list — leave it ticked to see everything, untick it to focus on what's still open.
      vi. Log "chasing" as a nested sub-task so the original task is never lost.
      vii. List / Roadmap views — a toggle at the top of the Actions tab switches the same tasks between the list and a visual "roadmap" (a timeline), for the current programme.
         1. Time axis runs left to right across the span of your task dates, with a vertical "today" marker. Saturday and Sunday columns are shaded light grey (at Day and Week zoom) so non-working days stand out. Zoom between Day, Week, Month and Quarter; it opens at Week, centred on today. "Today" re-centres.
         2. Lanes come from your headers (nested headers become nested sub-lanes); tasks with no header fall into a catch-all lane. Every task has its own line.
         3. A task with a start and a due date shows as a bar from start to due; a due-only task shows as a single marker. Each pill shows the task name and owner, and is coloured by its state; hovering it shows the dates plus the number of working days (weekdays) it spans, or for a lone marker how many working days away it is. A small coloured circle beside each task's name shows its first tag's colour, with a Tags key under the timeline saying which colour is which (an untagged task shows a hollow ring, so names stay aligned). Completed tasks appear greyed (hidden when "show completed" is unticked — the same toggle as the list).
         4. Folding a header or parent with the caret collapses its children, and that fold is shared with the list. Click anywhere on a task's row — its bar, marker, or name — to open its detail; this works even for a task with no dates yet, so you can add a start or due date straight from the roadmap. The detail opens as a pop-up centred in the current view (not inline), so the timeline doesn't jump around and the editor is always on screen no matter how far you've scrolled. Click another task to switch to it, and click outside the pop-up (or the ✕) to close it.
         5. Drag a bar to reschedule it — dragging the body moves the start and due dates together (keeping its length), and dragging either end handle changes just that date. Drag a lone marker to move its date. Dragging never opens the editor.
   d. Notes (was "Status")
      i. A general note-taking area with multiple pages — the page rail across the top switches between them, and "＋ Page" creates a new one.
      ii. Templates: Blank, Marketing plan (Vision, Problem and opportunity, Umbrella idea, How we roll this out, Sustainable ownership, What success looks like), M&E baseline framework (problem statement, core measurement question, and a baseline grid: topic / sentiment / key data points / COM-B lens / progress indicators / data collection), Stakeholder list (a spreadsheet grid: stakeholder, priority, details, opportunities, influence, interest, risks, relationship owner, next actions, engagement status), Behaviour change approach (per-behaviour insight plus a table where COM-B → Intervention functions → Policy categories → Behaviour change techniques cascade as dependent dropdowns from the Behaviour Change Wheel), and a Links database.
      iii. Each doc page is a Notion-style editor — press `/` in any block for headings, bullets, numbered lists, toggles (collapsible lists), callouts, tables, dividers, and inline links; pull in actions, events, contracts, POs or budget lines as clickable chips via `/link`. The slash menu is keyboard-driven: type to filter (e.g. `/h1`, `/number`), use ↑/↓ to move and Enter (or Tab) to insert the highlighted block — no need to click. In a list, Enter continues it (numbered items renumber automatically) and Enter on an empty item leaves the list. Tab / Shift-Tab indent and un-indent list items to nest them; nested numbered lists restart their own count while the parent list keeps going.
      iv. Select several blocks at once — drag across them, or click one and Shift-click another (Ctrl/Cmd-click toggles individual blocks) — then Ctrl/Cmd-C to copy, Ctrl/Cmd-X to cut, or Delete to remove them. Pasting multi-line text creates a block per line (recognising `-` bullets, `1.` numbers and `#` headings).
      v. The Links database page is a filterable table of the programme's key links (title, URL, category, notes) with one-click open.
3. Cross-linking
   a. Anything can link to anything: tasks ↔ contracts, PO lines, calendar events, budget lines, invoices, forecast lines (including planned spends, which carry their links through to the contract when converted).
   b. Chips are clickable everywhere and navigate to (and highlight) the target item.
   c. The ↩ badge on Overview rows and contracts lists everything linking back to them, including notes pages.
4. Exporting — all of these live under 📥 Data (see 1.d), which is the single export/import hub.
   a. 📊 Excel — a multi-sheet workbook (Overview, Contracts, Variations, POs, PO Lines, Invoices, Forecast, Actions, Calendar, Links, Notes).
      i. The file is SpreadsheetML (`.xls`); Excel opens it directly and may show a one-time format prompt — click Yes.
   b. 📝 Markdown — a full programme snapshot formatted for AI ingestion.
   c. 💾 JSON — the complete raw data, also AI-readable and re-loadable; uploading a JSON file back through 📥 Data updates all information in the app.
   d. Financial CSV — a round-trip of the financial data specifically, for editing in Excel and re-uploading.
5. Look and feel
